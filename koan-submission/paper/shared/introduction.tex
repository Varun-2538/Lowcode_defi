\section{Introduction}
\label{sec:intro}

Natural-language workflow generation is attractive for decentralized
finance (DeFi) because common user goals---token swaps, limit orders, and
cross-chain transfers---require coordinating multiple protocols and many
configuration choices. A system that turns ``swap 1 ETH to USDC with at
most 1\% slippage'' into an executable workflow could make DeFi accessible
to users who cannot write contract calls by hand.

Evaluations of such systems, however, typically stop at whether the
generated workflow, viewed as a directed graph of nodes and edges, is
structurally valid. We argue that this is the wrong bar for DeFi. A graph
that looks correct may still be unsafe or non-executable if it omits the
concrete trade parameters needed to run, ignores price-impact limits, uses
unsupported chains or tokens, or fails to gate execution against the cost
of the user's own order. In a domain where a single transaction can move
real funds irreversibly, structural validity is necessary but far from
sufficient.

This paper reframes DeFi workflow synthesis as a benchmark and measurement
problem centered on \emph{safe executability}. We evaluate generated
workflows on three nested static layers---structural validity, executable
configuration completeness, and declared safety---and, crucially, add an
execution layer that runs each generated swap on a real EVM and observes
the on-chain outcome. This lets us separate three questions that prior
evaluations conflate: does the graph have the right shape, does it carry
the parameters needed to execute, and, when executed, does it actually
behave safely?

Our central finding is that structural validity does not imply safe
executability, and the gap is large and consistent. Across a 120-prompt
benchmark and a range of systems---a deterministic template baseline, a
deployed no-code DeFi generator, and direct, constrained, few-shot, and
safety-instructed language-model baselines on two model families---the best
system reaches only $0.44$ structural validity and none exceeds $0.29$
safe-executability. On-chain, the direct, constrained, and few-shot
configurations each execute $10$--$13$ large swaps at roughly $33\%$
self-inflicted price impact because they set a slippage bound but no
price-impact gate. An explicit safety instruction is the only intervention
that removes on-chain unsafe execution, and even it leaves most workflows
structurally incomplete.

\paragraph{Contributions.} (1) We introduce \textsc{DeFiFlowBench}, a
120-prompt benchmark over four DeFi task categories with difficulty tiers,
paraphrase clusters, and adversarial cases, and a three-layer static
evaluation (structural, executable, safe) plus a clarification axis, with
safety predicates derived uniformly across systems. (2) We add an on-chain
execution layer that runs generated swaps on a real EVM and distinguishes a
slippage bound from a price-impact gate, turning ``declared safety'' into
``observed safety'', and we show the static safety proxy is sound against
this on-chain ground truth (no false certifications). (3) We calibrate the
scale with an oracle ceiling and null/random floors, report every rate with
confidence intervals, and provide a quantified failure taxonomy and
robustness analysis; we ablate constrained, few-shot, and safety-instructed
prompting to show the gap is real but only partially closable by prompt
design. (4) We release the prompts, gold annotations, baselines, execution
harness, and analysis code for reproducible evaluation.
